# 舵机工作台 0.1.1：先演练，再逐只配置

这是独立电脑工具，Tools主版本仍是0.6.0。支持XL330-M288与Feetech HD1910-C001，批次固定15个关节。它直接维护舵机寄存器，不修改robotd、IMU校正或升级管理器。**本轮仅完成本地软件验证，所有实机操作仍NOT_RUN，等待另行通知。**

## 先打开无硬件演练

解压便携ZIP或tar.gz，进入其中 `microduck-servo-workbench-0.1.1` 文件夹。电脑需已安装Python3.11+；模拟不需任何第三方包。

macOS / Linux：

```bash
./workbench.sh serve --demo --open
```

Windows PowerShell / cmd：

```powershell
.\workbench.cmd serve --demo --open
```

命令启动电脑本地网页并打开浏览器；地址为 `http://127.0.0.1:8766/`。保持终端运行，停止时按Ctrl+C。重复启动会恢复批次，以只读状态重新核对，旧预览作废。网页只监听本机，不是局域网远程控制入口。

## 页面只需记住三步

1. **准备套件**：选型号、布局、预设版本，点“建立15舵机批次”。默认不改变保护或增益；需要的特殊预设先展开说明再勾选。Microduck右腿10–14、左腿20–24；XGO左右相反，不能混用。
2. **逐只配置**：演练点“接入下一只新舵机”；真实操作则断电换机再上电。等待“已稳定 · 待确认”，核对实物标签、单舵机和型号两项声明。操作端完成声明后，未配置的新槽位会自动读取、备份并显示差异；只需点一次“确认本只配置”。改过标签/选项或需要重新预览时用“读取、备份并预览”。成功显示“读回通过 · 待掉电复核”。打印或抄下标签，关闭舵机电源，再换下一只。不建议带电拔插连接器。
3. **整组复核**：全部15只读回通过后，断电连接整组再上电。演练用“连接本批全部模拟舵机”和“模拟掉电重上电”。人工勾选已整组重上电，再点“检查全部15只的持久配置”。通过项显示“掉电复核通过”，失败槽位保留证据进入修复；最后导出JSON。

日常换机保留电脑、USB适配器及板端供电，仅切换舵机供电会更顺畅。工具不控制电源，“无回应”也不能证明已经断电。

每只配置只需一次写入确认；Reset Mid、保护设置、台架动作分别显式选择。重连、刷新、遥测和事件订阅都不会发起配置写入。已配置ID再次出现会选回原槽位，不自动分配给下一关节。相同型号/固件不代表同一实体，需核对实物标签。

## 连接状态怎么看

| 页面区域 | 看到什么 | 应做什么 |
|---|---|---|
| 工作台 / 板端代理 | 在线、重连中 | 电脑或SSH暂时断开时保持页面；不重新建立批次 |
| 串口适配器 | 已找到、未连接、需要选择、被占用 | 无可靠USB序列号或多个候选时手动重新选端口 |
| 舵机总线 | 等待回应、稳定读取、待确认、访问阻断 | 等待时可断电换机；阻断时按原始错误排查 |
| 关节卡片 | 读回通过 / 掉电复核通过 / 中断 | 单次读回不等于EEPROM掉电保存已验证 |

“立即检测”提前进行只读探测；“完整只读扫描”是补充操作，可能耗时较长，等待期间不会反复全扫描。“停止当前任务”取消后续动作，不能保证已发包的事务被撤销；卸力状态必须以读回为准。关闭页面会停止台架心跳，后台页面也不续期。

## 电脑USB模式（待现场授权后使用）

便携包带通用pyserial3.5 wheel，原生串口模式先做一次离线环境准备：

```bash
python3 tools/setup-workbench.py
./workbench.sh serve --real --open
```

Windows第一条用 `py -3.11 tools/setup-workbench.py`，第二条用 `workbench.cmd serve --real --open`。第一条只建立当前目录 `.venv-workbench` 并按固定SHA安装pyserial，不访问硬件；第二条打开网页，仍需手动刷新端口、选中正确适配器并点“绑定并只读连接”。适配器驱动、半双工接口、电压和接线需另行核对。

有VID/PID/可靠序列号时可跟随USB改名；多个候选、没有可靠序列号时不猜测。后台重启后仅可靠绑定会自动恢复只读检测，其余情况重新选端口，已有批次保留。模拟与真实批次不能交叉执行。

最少连线是适配器DATA→舵机DATA、舵机独立电源VCC、共GND；USB口供电能力不能代替舵机电源规格。XL330与HD1910使用不同协议和电压范围，必须先确认实际器件，禁止直接套用另一型号参数。

## 电脑—板端双端模式（待现场授权后使用）

板端是唯一串口执行者与SQLite权威，电脑仅显示和确认。先上传并解压同一便携tar.gz，再在板端**预览**安装计划：

```bash
python3 deploy/workbench/install-agent.py --kind hd1910 --port /dev/REPLACE_WITH_VERIFIED_UART
```

`--port`必须替换为核实过的UART；XL330改 `--kind xl330`。此命令只校验包和显示目标，不安装、不打开串口。另获现场通知后，才可以在Linux板上以root执行同命令加 `--apply`，安装Python源码和离线pyserial到 `/opt/microduck-servo-workbench/releases/0.1.1`，建立 `current` 指针。不会安装自启动服务或修改robotd。

板端需Python3.11+及venv/ensurepip；本包不是新的daemon二进制，不需编译robotd。板端ARM64环境、串口与实机尚未验证。代理安装失败保留部分版本供审查，旧current不切换；不要盲目重复安装或删除回滚材料。

由管理员事先核对SSH主机指纹并登记Host别名及唯一命令的sudo权限：

```text
sudo -n -- /opt/microduck-servo-workbench/current/agent.sh --stdio
```

此命令只作权限配置参考；不能授权任意Python/shell/sudo，不由网页写sudoers。维护前需现场人员按既定支撑、动力、policy等条件交接正式服务。代理要求robotd停止、没有手工robotd进程和其他串口持有者，否则拒绝维护，不替用户停服务。

电脑随后运行：

```bash
./workbench.sh serve --ssh duck-maintenance --open
```

`duck-maintenance`是已登记的SSH别名。此命令仅连接该主机的固定代理，不部署、停止服务或自动写舵机。SSH断开后自动只读重连；若板端重启使robotd恢复运行，显示维护阻断，等待人工处理。电脑与板端的两个独立数据库不会自动合并。

## 可选中位、台架与参数回退

展开“可选维护”，另外确认独立单舵机台架固定、可立即断电，逐次预览和确认：

- **HD1910 Reset Mid**：只发送一次0x0B，把当前机械位置定义为硬件2048。它不等于移动到2048，也不自动保持机械零位。固件契约3.43+，协议本身不能证明HD1910型号。应答后仍核对位置和偏移；不生效则停止，重连不重发。改变坐标后标记机器人校正需重新审查。
- **±3°台架检查**：仅装配前单只无负载、小幅有限轨迹，默认5°/s、3周期、最长20秒，前台独立心跳750ms，电流/温度/故障条件停止。会明确开启扭矩，结束尝试卸力并读回；断链后只能显示未知，不自动续跑。原生采样频率需实测，不能以请求20Hz当真实执行20Hz，不能证明额定扭矩或剩余寿命。
- **本任务参数回退**：只恢复该次配置实际修改的字段，先显示差异再确认；不恢复历史目标、Torque Enable或Reset Mid。回退后仍需要掉电复核。
- **当前设备只读检查**：显示原始故障、电压、温度、模式与读取错误，提供排查建议；未发现规则异常不能证明硬件完好。

## 文件在哪里，如何与Studio联动

| 位置 | 用途 |
|---|---|
| macOS：`~/Library/Application Support/Microduck/ServoWorkbench/` | 电脑默认状态目录 |
| Windows：`%LOCALAPPDATA%\Microduck\ServoWorkbench\` | 电脑默认状态目录 |
| Linux电脑：`~/.local/share/microduck-servo-workbench/` | 电脑默认状态目录 |
| `workbench.sqlite3`，同目录WAL/SHM | 批次、快照、事件、任务意图权威；停止后台后整体备份，不能只复制运行中的主文件 |
| `authority.lock` | 内核进程独占锁，退出即释放；不能靠删锁文件强行多开 |
| 板端 `/var/lib/microduck-servo-workbench/` | 板端执行模式的权威任务及报告 |
| 板端 `/etc/microduck-servo-workbench/agent.json` | 固定串口、协议与状态目录；root拥有，不是robotd.toml |
| Studio状态目录 `/servo-workbench-reports/` 子目录 | 导入的历史报告，不作为实时健康或执行许可 |

可加 `--state-dir /独立/目录` 指定一套独立权威。不要在真实模式中拿演练记录当实机记录。

在工作台“导出批次与证据”后，打开已配对Studio→“舵机工作台报告”→选择JSON→导入。该入口仅存储/查看历史证据，不会从Studio启动串口、初始化或测试。USB模式电脑权威、板端代理权威、Studio历史副本分别标识。

只读查看与导出也可用：

```bash
./workbench.sh status
./workbench.sh export --out servo-batch-review.json
```

前者读取已运行网页后端，后者导出当前批次到新文件；不会启动一个新的串口后台。多个浏览器可查看，同一时刻只有一个操作端。页面刷新保留会话；会话丢失时重新接管，仍须重新预览。

## 0.1.1复审变化

写入确认固定到同一适配器连接，事务中不能自动重开串口。Feetech回显和错误应答不当读数；完整扫描可选择型号速率表，最长180秒且可取消，唯一完整候选才接回只读稳定检测。ID/波特率回退中断后重新定位并只处理剩余差异。台架实际发包前复查750ms心跳和20秒总时限，准备阶段也计时；缺位置/速度或实际超出±5°观测窗口时停止，不能把请求5°/s当实测速率。只允许原连接明确卸力收尾，断链不重连写扭矩。旧0.1.0代理须结束维护会话后单独升级，0.1.1不静默兼容。
